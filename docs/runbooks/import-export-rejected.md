# Runbook — Import/Export Rejected

## Symptom

- `POST /api/references/import` rejects a valid file.
- `POST /api/references/import` accepts or tries to process a suspicious file name.
- `POST /api/references/export` fails with an invalid name or produces a corrupt download.

## How to reproduce

1. Import a valid file of a supported format.
2. Repeat with an empty file.
3. Repeat with a malicious name such as `../evil.ris`.
4. Repeat with a disallowed extension or MIME type.
5. Export with a normal name and then with an invalid name.

## What to check first

- Does the file meet the format and size allowlist?
- Is the final name generated by the server, or is the client's name still being used?
- Does the final path stay inside the allowed temporary directory?
- Are temporary files cleaned up even when the process fails?

## Expected logs and events

Business events emitted by `ReferenceController`
(full catalog in `docs/observability/event-catalog.md`):

- `event=reference.import outcome=success` (INFO), with `username`,
  `format` and `count`.
- `event=reference.import outcome=rejected reason=empty_file` (WARN):
  empty file.
- `event=reference.import outcome=rejected reason=unsupported_format`
  (WARN), with `format`: unsupported format.
- `event=reference.export outcome=success` (INFO), with `username`,
  `format` and `count`.

These events never log the file contents or the name the client
sent.

No event of their own: file parsing errors and other validation
rejections do not emit a business event. They only show up as an
`ErrorResponse` (ADR-011), with the `correlationId` in the
`X-Correlation-Id` header.

## Likely causes

- Path traversal or incorrect canonicalization.
- Disallowed type or size.
- Incomplete cleanup of temporary files.
- Rejection by the parser/format validation.
- Unsanitized `Content-Disposition` or export name.

## How to resolve

1. Confirm whether the rejection is a security, format or parser one.
2. Check the final normalized path and the generated physical name.
3. Review the per-environment limits and the file metadata.
4. Reproduce with a minimal integration test before the fix.
5. Validate import and export after the change, not just one of them.

## How to prevent recurrence

- Keep tests with malicious names, an empty file and an invalid format.
- Do not use the client's `originalFilename` or `fileName` as the final path.
- Document mitigations and residual debt in `docs/decision-log.md`.
